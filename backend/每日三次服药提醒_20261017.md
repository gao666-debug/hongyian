# 每日三时段服药提醒更新（2026-10-17）

版本：固件 v3.5.0 / App 1.3.0 / 后端 API 1.2.0。

## 行为

每天最多三个时段，分别开关、分别设置北京时间；默认 08:00 / 12:00 / 20:00，新增时段默认关闭，升级保留原第一时段设置与当天确认。时段不强制按先后排序；即使设为同一时间，也视为三个独立提醒，需按实际医嘱配置。

状态：未开启、时间待同步、待提醒、未服药、已服药。到时后板端蜂鸣/灯光提醒；App 在前台弹窗提示对应时段。每个时段可确认，也可撤销为未服药（App 撤销前二次确认）。关闭某时段不删除当天已有确认，重新开启仍保留；修改时间不清空当天确认。北京时间换日后开始新一天；重启保留设置与当天确认，但启动后仍需网络对时。

确认仅代表用户操作，不是传感器检测到实际服药。本次没有新增手机后台系统推送。

## 板端按键

K5 短按翻至生活提醒页；K6 进入编辑并循环选择：夜灯 → 第1时段开关/小时/分钟 → 第2时段开关/小时/分钟 → 第3时段开关/小时/分钟 → 第1/2/3时段服药状态。

K4 修改选中项。在“服药状态”项，按 K4 在未服药/已服药间修改，仅影响当天对应时段；确认已服药需达到该时段时间。开关与时间修改后长按 K6 保存。K5 离开取消未保存配置。报警时优先保留原求助/确认/消音操作。K5 长按仍是 AP/STA 切换并重启。

## 协议

保留 set_living 和 confirm_medicine 原命令，均只操作第一时段，不会覆盖第二、第三时段。新版 App 对旧固件仅显示/设置单次提醒，不显示三次功能假成功。

新增 set_medicine_plan，service_id=HomeSafety，paras 示例：

```json
{"night_auto":true,"medicine_enabled":true,"medicine_minute":480,"medicine_enabled_2":true,"medicine_minute_2":720,"medicine_enabled_3":true,"medicine_minute_3":1200,"expected_revision":1}
```

所有字段必填。时间为 0..1439 分钟，开关须是真正 JSON boolean。expected_revision 使用最新 living.config_revision。

新增 set_medicine_state：

```json
{"dose_day":20743,"slot":1,"taken":true,"expected_medicine_revision":1}
```

slot=0/1/2；taken=true 确认、false 撤销。dose_day 必须取当前设备状态，不能照抄示例；expected_medicine_revision 来自当前设备上报。结果 0 成功，1 参数/日期/未到时间/未开启，2 存储失败，4 状态版本冲突。冲突后刷新状态，勿盲目重试。原 client_request_id 幂等机制仍有效。

健康消息外层 schema 保持 1，living.schema 改为 2，保留原第一时段字段，并新增 medicine_revision 和 slots（固定三项，slot 按 0/1/2 顺序）。每项含 slot/enabled/minute/state/confirmed_epoch。夜灯仍按任一未服药提醒优先让灯。

## 后端部署（给服务器维护者）

更新包为完整公开源代码，不含 .env、云密钥、数据库、私钥。**保留服务器原 .env、.local/数据库和 .venv，不能以本地文件覆盖。** 本次无新依赖、无需数据库迁移；使用现有 documents 表保存服药历史。

需更新 backend/app.py、backend/medicine.py（新文件）、backend/store.py；建议按原完整代码覆盖公开源文件。保持原 127.0.0.1:8000、单 worker 与 nginx 不变，按原服务名称重启 API 与 AMQP 消费者。不要在本机和服务器同时启动同一队列消费者。

华为云两个新命令已在开发端新增并回读核对，不需要重复改物模型。tools_living_model.py 仍可用于只读核对/幂等补齐，保留旧属性、事件和命令。

新增 GET /api/v1/devices/{device_id}/medicine/history?limit=50，Bearer 鉴权不变，返回 {code:0,data:{items:[...]}}。每项 dose_day、slot、state、minute、confirmed_epoch、medicine_revision、epoch；来自实际接收的健康状态变化，包含板端按键。中间发生多次操作而板子尚未上报的瞬时变化可能无法恢复，不生成虚假历史。App 在生活提醒设置页展示最近记录；离线期间未接收的状态不会伪造。

部署顺序：先后端 → 确认 /healthz 正常、匿名业务 401 → 刷固件 → 安装 App → 看到 living.schema=2、三个 slots → 配置近一分钟提醒验证 → 分别确认/撤销 → 重启核对持久化及历史。

本次本地测试与模拟器验证不等于服务器已部署、实板已刷入或真机端到端已通过。固件须使用配套镜像按原烧录方法更新，勿误刷源码包。
