## 1.9.1 合并补充

- `client_id` 按发送账号和会话隔离；相同编号、相同内容重试返回原消息，相同编号改内容返回 409。兼容 1.9.0 已存消息。
- 实时消息也发给发送者账号的连接，用于多手机同步。App 必须按消息 `id` 去重（HTTP 回包和 WS 可能同时到达）。
- 群主暂不允许退群，返回 409，避免群主退出后仍保留管理权限；普通成员可退出，群主可移除普通成员。
- 邀请码消费、单聊创建、重试发送及群容量检查增加事务保护；上传逐块限制为 8 MB，会话非成员不能上传。
- WebSocket 在实际发送前重新检查登录状态和会话成员资格；媒体响应不缓存，防止退出会话后复用缓存读取。
- 消息分页时间戳保持严格递增，避免同时发送时游标遗漏。

以下接口与 1.9.0 保持兼容。本文消息是账号之间的聊天，尚不代表主板与 App 的留言功能已接通。

## 一、先看三个前提

### 1. 消息「先落库、再推送」

对方在线 → WebSocket 立刻收到；对方离线 → 消息躺在库里，下次打开拉历史即可。
所以**不依赖 Push Kit**，也不会丢消息，只是不"秒达"。

### 2. App 不需要新开 WebSocket

现有的 `/api/v1/ws` 连接建立时，服务端已经知道登录账号，**同一条连接会自动收到聊天消息**：

```json
{ "schema": 1, "type": "message", "conversation_id": "…", "timestamp": "…", "data": { …消息体… } }
```

⚠️ **但前提是 App 保持着一条 WS 连接**。现有逻辑是「要先登录 → 拿 ticket → 用某台 device_id 建连」。
所以 App 在进入消息页之前，至少要有一条连接（用主设备 ID 建即可），否则收不到实时推送。
**没有连接也不影响功能**——打开会话时拉历史就行，只是不实时。

### 3. 单聊和群聊是同一套模型

单聊 = `kind='direct'` 的会话，群聊 = `kind='group'`。前端可以复用同一套聊天页。

## 二、好友（邀请码制）

### 2.1 生成邀请码

```
POST /api/v1/contacts/invite
```

**响应 201**

```json
{ "code": 0, "data": { "code": "J5L2GG", "expires_at": "2026-11-12T12:41:00Z", "ttl_seconds": 604800 } }
```

- 6 位大写字母+数字，已剔除易混字符 `0/O/1/I`
- **一次性**：被使用后立刻失效（再用返回 409）
- **7 天过期**（过期返回 410）

### 2.2 用邀请码加好友

```
POST /api/v1/contacts/accept
{ "code": "J5L2GG" }
```

**响应 200** → `{ "data": { "peer": "guardian", "status": "accepted" } }`

添加后**双方互为好友**（各写一条），不需要对方再确认。

| 错误码 | 含义 |
|---|---|
| 404 | 邀请码不存在 |
| 409 | 已被使用 / 已经是好友 |
| 410 | 已过期 |
| 422 | 不能加自己 |

### 2.3 好友列表 / 删除

```
GET    /api/v1/contacts      → { "items": [ { "username": "bob", "since": "2026-11-05T…" } ] }
DELETE /api/v1/contacts/{peer}
```

删除后双方关系一起解除；已有会话和消息**不会删除**，但发新消息前需要重新加好友。

## 三、会话

### 3.1 会话列表（首页数据源）

```
GET /api/v1/conversations
```

**响应**（按最后消息时间倒序）

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "conversation_id": "7f3a…",
        "kind": "direct",
        "title": "bob",
        "name": null,
        "owner": "guardian",
        "peer": "bob",
        "members": ["guardian", "bob"],
        "member_count": 2,
        "unread": 3,
        "last_message": {
          "id": "a1b2…", "conversation_id": "7f3a…", "sender": "bob",
          "kind": "text", "body": "妈，吃药了吗", "duration": null,
          "created_at": "2026-11-05T12:30:00Z"
        },
        "last_message_at": "2026-11-05T12:30:00Z"
      }
    ]
  }
}
```

- `kind='direct'` 时 `title` 就是对方用户名，`peer` 有值
- `kind='group'` 时 `title` 是群名，`peer` 为 `null`
- 会话还没消息时 `last_message` 为 `null`

### 3.2 打开（或创建）单聊

```
POST /api/v1/conversations/direct
{ "peer": "bob" }
```

- 幂等：同一对好友永远只有一个会话，重复调用返回同一个 `conversation_id`
- **必须是好友**，否则 403

### 3.3 建群

```
POST /api/v1/conversations
{ "name": "颐鸿安之家", "members": ["bob", "zhangsan"] }
```

- 最多 **10 人**（含创建者）；`members` 传 1~9 个
- 所有成员**必须已经是创建者的好友**，否则 403
- 创建者是群主

### 3.4 改群名 / 加人 / 踢人 / 退群

```
PATCH  /api/v1/conversations/{cid}                  { "name": "新群名" }        // 仅群主
POST   /api/v1/conversations/{cid}/members          { "username": "carol" }     // 仅群主
DELETE /api/v1/conversations/{cid}/members/{username}                           // 群主踢人，或本人退群
```

- 群满 10 人时加人返回 422
- 被踢/退群后**立刻失去该会话的读取权限**（403），历史消息仍在库里
- 群主**不能解散群**（避免误删历史）

## 四、消息

### 4.1 发文本

```
POST /api/v1/conversations/{cid}/messages
{ "body": "妈，记得吃午饭", "client_id": "本地唯一ID" }
```

**响应 201**

```json
{ "code": 0, "data": {
    "id": "a1b2…", "conversation_id": "7f3a…", "sender": "guardian",
    "kind": "text", "body": "妈，记得吃午饭", "duration": null,
    "created_at": "2026-11-05T12:30:00Z" } }
```

> `client_id` 建议必传（可用 UUID）。**同一账号在同一会话内、同内容重复提交只会产生一条消息**，
> 网络不好重试不会出现两条一样的消息。

### 4.2 发图片 / 语音：两步

**第一步：上传媒体（原始字节，不是 multipart）**

```
POST /api/v1/media?conversation_id={cid}
Content-Type: image/jpeg            （图片）或 audio/mp4 / audio/m4a / audio/aac / audio/amr（语音）
Body: 文件原始字节
语音还要带 duration：POST /api/v1/media?conversation_id={cid}&duration=12
```

**响应 201**

```json
{ "code": 0, "data": { "id": "9c8b…", "kind": "voice", "size": 20480, "duration": 12.0, "content_type": "audio/mp4" } }
```

校验规则：

| 项 | 规则 |
|---|---|
| 大小 | ≤ 8 MB（nginx 也是 8M） |
| 图片 | 只收 JPEG / PNG，会校验文件头 `FF D8` 或 `89 50 4E 47` |
| 语音 | 只收 m4a/aac/amr，分别检查 `ftyp`、ADTS 或 AMR 文件头 |
| 语音时长 | **1~60 秒**，必传 `duration`，超范围 422 |
| 不支持的类型 | 415 |

> 注意：上传时必须带 Content-Type，服务端靠它判断类型；文件头对不上会 415。
> 语音**不做服务端转码**，原样存储，所以 App 录什么格式就播什么格式。

**第二步：把媒体作为消息发出**

```
POST /api/v1/conversations/{cid}/messages/media
{ "media_id": "9c8b…", "client_id": "本地唯一ID" }
```

**响应 201** → 结构与文本消息相同，`kind` 为 `image` 或 `voice`，`body` 是 `media_id`

### 4.3 拉历史（分页）

```
GET /api/v1/conversations/{cid}/messages?limit=30&before=1730000000
```

**响应**

```json
{ "code": 0, "data": {
    "items": [ …按时间正序，最早在前… ],
    "limit": 30,
    "has_more": true,
    "next_before": 1730000000.123 } }
```

- `limit` 1~100，默认 30
- 首次不带 `before`；继续往上翻时把上次返回的 `next_before` 传进去
- `items` 是**时间正序**（便于直接追加到列表底部）

### 4.4 标记已读 / 未读总数

```
POST /api/v1/conversations/{cid}/read        → { "data": { "conversation_id": "…", "read_at": "…" } }
GET  /api/v1/messages/unread                 → { "data": { "unread": 5 } }
```

> 未读 = 所有会话里「别人发的、且晚于我的 `last_read_at`」的消息总数。
> 进入会话时调一次 `/read`，未读数就会清零。

### 4.5 下载媒体

```
GET /api/v1/media/{media_id}
```

- **必须登录，且必须是该会话成员**，否则 403（没有裸 URL）
- 返回原始字节 + 正确的 Content-Type，可直接喂给图片组件 / 播放器
- 带 `Cache-Control: private, no-store`，客户端不应持久缓存敏感媒体

## 五、WebSocket 推送

现有连接会自动收到两类新事件：

```json
{ "schema": 1, "type": "message", "conversation_id": "7f3a…",
  "timestamp": "2026-11-05T12:30:00Z", "data": { 与发送接口返回的消息体相同 } }
```

```json
{ "type": "resync_required", "timestamp": "…" }
```

- `type='message'`：会话有新消息（推给所有成员，包括发送者的其他设备；按消息 ID 去重）
- `type='resync_required'`：**消息队列积压**（同一账号短时间内收到太多），
  收到后应该断开重连并**重新拉会话列表**。注意这个事件的 `resync_required` **没有 `device_id` 字段**，
  而设备事件的同名事件是有的，前端要区分处理。

## 六、错误码速查

| 码 | 场景 |
|---|---|
| 401 | 未登录 / 会话过期 |
| 403 | 非好友发单聊、非会话成员读写、非群主做管理操作；聊天身份不授予设备控制权限 |
| 404 | 邀请码不存在、对方账号不存在、媒体不存在 |
| 409 | 邀请码已用、已是好友、同重试编号内容冲突、群主尝试退出 |
| 410 | 邀请码过期 |
| 413 | 媒体超过 8MB |
| 415 | 媒体类型不支持 / 文件头不符 |
| 422 | 参数错（群超 10 人、语音时长超 60 秒、加自己为好友、媒体跨会话引用） |

## 七、App 端实现建议（踩坑提示）

1. **语音录制**：录完先确认能拿到时长（秒），上传时必传 `duration`，否则 422。
   格式建议直接录 `m4a`（`audio/mp4`），服务端不转码，播出端要能播 m4a。
2. **图片**：先压缩再上传。8MB 是硬限，手机直出照片经常超。JPEG 质量 70~80 一般 200KB 以内。
3. **不要用 multipart**：上传接口收的是**原始字节**，`Content-Type` 决定类型。
   ArkTS 的 `request` 直接传 `ArrayBuffer`，不要包 form-data。
4. **`client_id` 一定要传**：弱网重试时能防止重复消息。
5. **进入会话就调 `/read`**，否则未读数不清零；退出会话不需要额外操作。
6. **WS 连接要保住**：消息推送依赖现有连接。如果 App 在首页建过连接，消息页可以直接复用。
   断线时（`resync_required` 或心跳超时）要重连并重拉会话列表。
7. **群聊已可用**：后端这次的会话模型已经把群聊做完了，前端可以直接接，不用等第二批。
