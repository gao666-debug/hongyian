# 消息后端合并说明

来源：队友 `messaging_1.9.0.patch`，原始提交 `71c1b0f7e09d3e622249b191ed2b8743dac3af46`，基于 main `b837b676f8c0772e0c2648a377f96d2e652c726a`。

本次将好友邀请码、单聊、十人以内群聊、文本/图片/语音、未读及账号维度 WebSocket 推送纳入仓库，并修复跨会话重试编号隔离、并发消费邀请码、群主退出权限、媒体流式大小限制与登录失效后的推送检查。版本为 API 1.9.1。

验证：仓库基线全部后端用例加消息用例共 64 项通过。测试使用临时数据库和本地测试客户端，没有连接生产数据库，没有改云平台配置或主板固件。

## 给服务器维护者

队友交接说明称服务器已运行 1.9.0。原始补丁回填仓库本身无需重部署，但本次还包含 1.9.1 修复，因此需要维护者同步代码并重启现有 API 服务才能生效。不要另外启动第二个 AMQP 消费者。

1. 备份现有数据库及媒体目录；保留 `.env`、数据库和 `.local/media`。
2. 从合并后的 main 更新代码，沿用原虚拟环境与启动命令；本次没有新增依赖。
3. 重启现有 API 服务。消息表自动创建，旧数据保留；重试编号兼容旧版，无需清库。
4. `/healthz` 应返回 `api_version=1.9.1`；匿名访问 `/api/v1/contacts` 应为 401。
5. 使用两个测试账号添加好友、发送消息，检查历史及未读；同账号重复请求不增加记录，不同会话使用相同 `client_id` 不串消息。测试完成后清理测试账号/数据应沿用服务器既有流程。

## 范围

本次只合并消息后端和文档，未上传任何 `.env`、账号密码、云密钥、媒体或生产数据库。App 聊天页面、录音/图片选择尚未接入；Push Kit 继续搁置，不保证锁屏或结束进程后即时通知。主板与 App 留言、账号权限细分及账号删除的本机开发改动不包含在此次消息补丁中，后续需要单独整合验收。

已知限制：无群主转让、解散群、消息撤回；媒体暂没有总容量配额和自动清理，服务器维护者需监控磁盘。文件头校验和声明时长不等于完整媒体解码校验；消息内容不用于自动执行设备命令。
