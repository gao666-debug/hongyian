## 1. 主板语音控灯

固件 v3.5.44，位于同目录「主板语音控灯_v3.5.44」。按原 RKDevTool 流程烧录 Firmware.img；尚未实板烧录验证。

沿用官方 d1_smart_home 的 SU-03T 原厂串口协议（115200 8N1）：开灯 `01 01`，关灯 `01 02`，自动模式 `00 01`，关闭自动 `00 02`。处理拆包、粘包及 500 ms 半包超时。温湿度查询仍为 `03 01`、`03 02`。

语音控制的是主板 RGB 夜灯，不是家用 220V 灯。开关灯是临时覆盖，重启或 App/板上保存生活设置后恢复所设自动夜灯；求助、环境报警与服药提示仍优先，关灯不关闭警报灯。不修改物模型和后端命令。语音模块本身必须配置了上述输出词条；目前串口硬件无法从软件保证修复。

## 3. 摄像头

- 流畅模式：读取现有摄像头 81 端口 MJPEG 连续流；80 端口鉴权获取访问许可，不把账号密码拼进 URL。
- 省流模式：完成一次取图后等待 1 秒再请求，失败重试。
- 原生 JPEG 解码，解码忙时只保留最新待解码帧，避免积压造成越来越迟。
- 截图：JPG，需近 5 秒内有有效帧，系统选择保存位置；模拟器已验证选择器打开，完整截图写入尚待复验。
- 录像：无声 MJPEG AVI，最长 60 秒，缓存最多 16 MB，输出最多 32 MB；按 5 fps 时间轴保持间隔缺帧，停止后点保存录像。录像不等同录像源达到 5 fps，也不产生不存在的运动细节。部分手机播放器未必支持 AVI，MP4 转码未实现。
- 录像期间可截图；切换画质模式需先结束录像。退出会结束录制，但未导出的录像只在当前页面实例内，务必先保存再退出。
- 仅限同一局域网，没有实现公网转发、后台录像或全天监控存储。
- App 摄像头页面要求家庭账号已登录；摄像头本身仍独立校验本地账号。

## 4. 多手机、家庭成员

本地后端已有 `/api/v1/household` 和 `POST /api/v1/household/members`，App「我的」页面对家庭管理员显示成员创建表单。

管理员账号 owner 可创建 viewer（只读）或 caregiver（照护，可操作）。其他手机安装 App，填写同一服务器地址，用各自账号登录即可。每台手机获得独立 Token，不使用硬件设备 ID 登录 MQTT，不顶掉开发板。服务端按成员所属家庭检查设备权限，未知设备 404、只读控制 403。

当前公网实测：`/healthz` 200，`/api/v1/household` 404。说明线上尚未部署已有家庭账号代码，不能声称公网多账号已完成。

给服务器维护者：使用仓库 main 中已合并的 backend 家庭权限版本，保留服务器 .env 与 SQLite 数据库，不用交付包覆盖它们；安装依赖，重启现有 API 服务，再验收：匿名 household 401、管理员 household 200、创建成员 201、新成员登录 200、viewer 命令 403、越权设备 404。数据库迁移由 Households 初始化 CREATE TABLE IF NOT EXISTS 自动完成。设备 ID 仍在服务器环境配置，三个物理设备分别持有自己的 IoTDA 身份。
