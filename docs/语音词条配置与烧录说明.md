# 语音词条配置与烧录说明（SU-03T）

主板 `device/rk2206_home_safety` 的语音功能由板载 **SU-03T** 模块承担。代码里已经把词条编号、串口协议、播报策略全部写好，但 **SU-03T 出厂只有 1~3 号数值词条和几条查询词**，4~23 号词条必须先在模块里配出来并烧录，主板发过去的帧才有声音。

这份文档就是补上「配词条 + 烧录 + 验证」这一段。之前只在 `include/su_03t.h` 的注释里列了编号，模块侧没有实际配置，凡是没配的编号，主板发出后模块会直接忽略（无声，不报错）。

---

## 1. 硬件与串口

| 项目 | 取值 |
| --- | --- |
| 模块 | SU-03T（板载，离线识别 + TTS） |
| 连接 | 主板 UART2：`GPIO0_B2`(TX) / `GPIO0_B3`(RX) |
| 波特率 | **115200**，8 数据位，无校验，1 停止位，无流控 |
| 代码位置 | `src/su_03t.c`，`su03t_init()` 里配置 |

模块供电与麦克风/喇叭按模块手册接线；烧录时用 USB-TTL 接模块的下载口，烧完再插回主板。

---

## 2. 帧格式（主板 ↔ 模块）

**模块 → 主板（识别结果，两字节）**

```
<前缀> <参数>
例：0x13 0x01   → 开灯
    0x10 0x01   → 紧急呼救
```

**主板 → 模块（播报固定句，六字节）**

```
AA 55 <词条号> 00 55 AA
例：AA 55 0D 00 55 AA → 播第 13 号「已发出紧急求助」
```

**主板 → 模块（播报数值，十三字节）**

```
AA 55 <数值词条号> <8 字节 double，小端> 55 AA
例：AA 55 01 <temp 的 double> 55 AA → 播温度
```

> 数值帧要求模块侧把该词条配成「变量播报」，变量类型选 **8 字节 double / 小端**，否则会播成乱码或 0。

## 4. 识别词条表（模块 → 主板）

每条识别词在平台里配「串口输出」为下表的两字节，主板对参数做范围校验，非法参数直接丢弃。

| 前缀 | 参数 | 建议口令 | 效果 |
| --- | --- | --- | --- |
| `0x10` | `0x01` | 小颐救命 | 发起紧急求助（等同按键呼救） |
| `0x10` | `0x02` | 小颐没事了 | 解除求助 / 确认报警 |
| `0x11` | `0x01` | 小颐静音 | 静音蜂鸣与播报 |
| `0x11` | `0x02` | 小颐恢复播报 | 取消静音 |
| `0x12` | `0x01/02/03` | 小颐我吃过药了（第 1/2/3 时段） | 确认对应时段服药 |
| `0x12` | `0x04` | 小颐确认服药 | 确认当前待服药时段 |
| `0x13` | `0x01` | 小颐开灯 | 夜灯常亮（临时覆盖） |
| `0x13` | `0x02` | 小颐关灯 | 夜灯关闭 |
| `0x13` | `0x03` | 小颐自动灯光 | 恢复自动夜灯 |
| `0x14` | `0x01` | 现在温度多少 | 播报温度 |
| `0x14` | `0x02` | 现在湿度多少 | 播报湿度 |
| `0x14` | `0x03` | 燃气浓度多少 | 播报燃气是否超标 |
| `0x14` | `0x04` | 光照多少 | 播报光照值 |
| `0x14` | `0x05` | 温湿度多少 | 先温度、1.4 秒后湿度 |
| `0x15` | `0x01` | 看第一页记录 | LCD 记录第一页 |
| `0x15` | `0x02` | 看第二页记录 | LCD 记录第二页 |
| `0x15` | `0x03` | 返回主页 | LCD 回主页 |

出厂遗留前缀仍然兼容，不必删：`0x01 01/02` 开关灯、`0x00 01/02` 自动/关灯、`0x03 01/02` 温度/湿度（`0x03 03` 出厂是光照，主板不响应）。

## 5. 配置与烧录步骤

0. **先跑一致性检查**（30 秒，能挡掉最常见的一类返工）：

   ```bash
   cd device/rk2206_home_safety
   python tools/check_voice_table.py           # 词条号、十六进制、指令前缀逐条比对
   python tools/check_voice_table.py --frames  # 顺带打印每条播报该发的串口帧
   python tools/check_voice_import.py          # 导入表 vs 固件（帧前缀、消息号、参数范围）
   ```

   `check_voice_table.py` 把 `su_03t.h` 的 `SU03T_SAY_*` / `SU03T_PFX_*` 与词条表对齐，
   报「头文件有、词条表缺」「参数超范围」「前缀固件不处理」。
   `check_voice_import.py` 检查即将导入平台的 Excel 表：发送协议的前缀固件认不认、
   接收协议的消息号固件发不发、同端口消息号有没有重复（重复会被平台直接阻断导入）。
   两个脚本退出码非 0 就先改表，别急着烧。

1. **建产品**：打开 SU-03T 的配置平台，新建一个产品，模块型号选 SU-03T，语言选普通话。
2. **用导入表配词条，不要手敲**：点顶部「导出模板」拿到官方 Excel 模板，把 `docs/语音词导入_小颐.xlsx` 的内容填进去（或直接用这份成品），再点「导入语音词」。
   - 共 **39 行**：19 条命令词（`串口输出` 为 6 字节帧）+ 20 条播报（`触发方式=串口输入`，靠接收帧触发）
   - 播报**不依赖平台编号**，所以不存在"编号错位播成温度"的问题
   - 详细字段含义见下面 5.1
3. **删掉模板自带示例**：`打开台灯 / 关闭台灯 / 调亮 / 调暗` 这 4 条必须删。它们发的是 `AA 55 00 01 00 09 55 AA`，主板会把 `00 01` 解析成「灯光自动」——说一句"打开台灯"就变成切自动灯。
4. **配数值播报**：1~3 号（温度/湿度/光照）保持平台出厂的变量播报，串口输入类型 8 字节 double、小端。**这三条不要改成固定句**，否则温湿度播报失效。
5. **生成固件**：平台导出 `.bin`，用 USB-TTL 接模块下载口烧录（具体引脚与工具以模块手册为准）。
6. **接回主板**：模块插回 UART2，确认 TX/RX 交叉、共地。
7. **打开主板开关**：`include/home_safety.h` 里把 `VOICE_DEDICATED_IDX` 改为 `1`（报警 4~8 与应答 10~23 一起启用），服药播报再把 `SU03T_MEDICINE_PROFILE_ENABLED` 改为 `1`。
8. **重新编译烧主板**：见 `device/rk2206_home_safety/README.md` 的构建说明。

### 5.1 导入表各列怎么填（`语音词导入_小颐.xlsx`）

命令词模板表的表头在**第 14 行**，A~H 八列：

| 列 | 含义 | 本项目的填法 |
|---|---|---|
| A 行为名称 | 必填，同名则整行覆盖原配置 | `VoiceHelpOn`、`Say04` 这类英文名 |
| B 触发方式 | 只能填「命令词」或「串口输入」 | 说一句 → 命令词；主板发帧让它念 → 串口输入 |
| C 串口 | 下拉只允许 `UART1` | 统一 `UART1` |
| D 命令词 | 多个用 `\|` 分隔，**不要带唤醒词** | `开灯\|把灯打开\|打开灯` |
| E 发送协议 | 命令词行填：模块发给主板的帧 | `AA 55 13 01 55 AA` |
| F 接收协议 | 串口输入行填：主板发给模块的帧 | `AA 55 0A 00 55 AA` |
| G 回复语 | 命令词行=应答；串口输入行=播放内容 | 命令词行**留空**，交给主板统一应答 |
| H 备注 | 自由填写 | 标注对应的固件词条号 |

**为什么命令词行要留空 G 列**：主板收到指令后会自己发一帧应答（如 10 号"已开灯"），
延迟只有几十毫秒。G 列再填一句就会连播"好的 · 已开灯"，反而啰嗦。

**为什么播报用「串口输入」而不是靠编号**：主板发的 `AA 55 <号> 00 55 AA` 里，
平台只按「帧头 + 消息号 + 参数 + 帧尾」匹配，<号> 就是消息号。这样 4~23 号
各对应一条固定句，与平台自动排出来的词条序号无关，改一条不影响其他条。

**帧头帧尾不要动**：UART1 保持模板预填的 `AA 55` / `55 AA`。这与模块引脚配置里的
出厂格式一致，导入时不会触发"改写端口为自定义格式"，出厂的温度/湿度/光照
数值播报得以保留。

**语音词表（第 2 个工作表）**：

| 项目 | 填法 | 说明 |
|---|---|---|
| 唤醒词 | `小颐小颐` | 3~6 字，不要写多个近音词，会互相抢 |
| 唤醒回复 | `我在\|你说\|有什么可以帮到你` | 随机播一条 |
| 免唤醒命令词 | 留空 | 老人用"小颐"唤醒更稳，免唤醒易误触 |
| 防误识别词 | 留空 | |
| 开机播报 | `无` | 关掉。上电的就绪提示由固件发 23 号帧负责，否则会念两遍 |
| 超时退出回复 | `有需要再叫我\|没事我先退下` | |
| 退出命令 | `退下\|你走吧\|先这样\|不聊了` | 至少保留 1 条 |
| 退出回复 | `有需要再叫我` | |

## 6. 烧录后怎么验证（不用一条条试）

### 6.1 先看「语音已就绪」

固件默认（`SU03T_BOOT_READY=1`）在**上电 1.5 秒后播一句「语音已就绪」（23 号）**。
听到这一句，说明 UART2、模块、词条三样都通了；听不到就别往下测，先查这三处。

串口日志对应：

```
[voice] boot greeting queued: index 23
```

如果日志有这句但模块不响，说明帧发出去了、模块没识别到 → 查波特率（115200 8N1）、TX/RX 是否交叉、23 号词条是否真的烧进去了。

### 6.2 再跑逐条自检

固件内置了上电自检：

```bash
# 临时打开自检：上电后从 4 号到 23 号逐个播报，每句间隔 2 秒，约 40 秒播完
# 在编译参数里加 -DSU03T_SELF_TEST=1
```

串口日志会同步打印，哪条没声音、播错，一眼能对上号：

```
[voice] self test queued 4..23
[voice] self test index=4
...
[voice] self test index=23
```

验证完**务必把 `SU03T_SELF_TEST` 改回 0**，否则每次开机都会念一遍。若日志打印 `self test skipped (VOICE_DEDICATED_IDX=0)`，说明第 7 步的开关没打开。

人工验收清单：

- [ ] 上电 1.5 秒内播「语音已就绪」（23 号）
- [ ] 喊「小颐」有应答，5 秒内能接指令
- [ ] 「小颐开灯 / 关灯 / 自动灯光」→ 灯变化 + 播 10/11/12 号
- [ ] 「小颐救命」→ 蜂鸣与红灯起，播 13 号；「小颐没事了」→ 解除并播 14 号
- [ ] 「小颐静音」「小颐恢复播报」→ 播 15/16 号
- [ ] 「现在温度多少」→ 播真实温度，不是 0
- [ ] 「燃气浓度多少」→ 正常/偏高分别播 21/20 号
- [ ] 制造一次无活动报警 → 播 4 号，不是温度模板
- [ ] 断电重启后以上仍成立

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 报警时播「温度 0 度」 | `VOICE_DEDICATED_IDX` 还是 0，报警编号落到了出厂数值词条 | 改 1 并重编主板 |
| 只有 1~3 号有声音 | 4~23 号未在模块配置 | 按第 3、4 节补词条并重烧 |
| 上电没有「语音已就绪」 | 23 号未配 / `VOICE_DEDICATED_IDX=0` / `SU03T_BOOT_READY=0` | 先确认串口日志有 `boot greeting queued: index 23` |
| 播报顺序错乱、说的是别的句子 | 平台自动编号与代码不一致 | 核对编号，必要时按顺序重建 |
| 温度播成乱码/负数 | 数值帧不是 8 字节 double 小端 | 改模块串口输入类型 |
| 完全无声音 | 波特率不是 115200，或 TX/RX 接反 | 核对接线与 `su03t_init()` |
| 串口日志有发送、模块不响 | 该编号词条为空或未启用 | 用自检模式逐条核对 |
