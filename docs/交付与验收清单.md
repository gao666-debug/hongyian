# 颐鸿安：基础要求补齐与 App 灯控

版本：App 1.12.0、API 1.8.0、主板 v3.5.50。

## 本次功能
1. 首页/设备页显示星闪环境节点的最近8条门窗变化记录。首次上报只建立基线；重复状态不重复记事件。后端每设备保留最近1000条，接口最多返回100条。
2. 门窗辅助提示：夜间开启、持续开启10分钟、数据过期。提示是待核实观察，不认定外出或异常入侵，不自动触发高风险报警。当前以服务器收到报告时间记录，无法补出断网期间未上报的开关变化。
3. 家庭设备页：固定节点显示外接供电；手表仅使用实际 battery_percent 字段，没有则“暂无数据”。需手表固件真实采样才能得到电量。
4. App 生活提醒卡片增加开灯/关灯/恢复自动；不改服药计划。主板使用既有灯光仲裁，报警 > 服药 > 夜灯。强制关灯只关闭夜灯，不关闭报警灯。手动设置不持久化；重启或保存生活设置后恢复原自动策略。
5. 保留主动呼救、批量处置、上次活动具体时间、昨日与前日对比、周/月已观察数据汇总、手表跌倒统一报警及家庭账号权限。

## 部署顺序（队友服务器）
1. 用后端包覆盖代码；保留现有 .env、数据库、证书。安装 requirements.txt，重启现有 API 与消费者服务。无需重建数据库。
2. 华为云主板产品的 HomeSafety 服务新增命令 set_light，请求参数 mode 为整数，最小-1、最大1：-1恢复自动，0关，1开。沿用现有命令执行回执约定。不要在星闪/手表产品中误建命令。
3. 烧录主板 v3.5.50，安装签名后的 App 1.12.0。旧固件不支持新命令，App 将提示执行失败，不能据提交成功认定灯已改变。
4. 生活状态新增可选 light_mode=-1/0/1，旧版本未上报该字段仍可读取健康数据。
5. 门窗依赖真实环境板 device.property 通路；没有上报就显示等待，不生成模拟记录。

## 状态与剩余验收
- 自动化测试：门窗基线/去重/过期/长开、灯控校验/优先级、双客户端接警/处置广播/断线补拉；原统计、手表、权限等回归。具体结果见测试日志。
- 构建通过与软件测试不能代替三块板实测：持续运行温湿度、PIR灵敏度、真实门窗开合、真实跌倒、手机确认与重新查询处置记录，仍需硬件到齐后验收。
- 后台通知：现有本地通知与前台 WebSocket 不代表 App 被关闭后仍可收到。按用户决定，Push Kit 暂不接入，配置步骤见单独文档。
- 暂不做无线按钮、星闪自组网、4G；语音留到最后单独处理。
- 本包不包含服务器凭据。HAP为未签名构建，实机需沿用原签名流程。
