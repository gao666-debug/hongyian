# 颐鸿安更新说明（2026-11-05）

## App 1.13.4

统一沉稳蓝、浅灰白和少量暖金，重新绘制环抱之家矢量图标；守护、报警、趋势、设备、我的五栏及生活提醒详情统一排版。保留夜灯、三个服药时段、确认与撤销、历史、报警备注、设备命令与回执、摄像头及手表相关功能。

实时刷新改为独立查询设备影子，统计、健康等慢请求不再阻塞实时查询。查询频率不代表板子上报频率；板子未上报时仍显示最近一次真实记录。

批量处理布局未调整：报警页底部“更多操作” → “一键处理全部”，随后选择当前加载的待处理记录或仅已结束的旧报警。批量保存处置记录，不删除历史，也不代替设备 ACK。

趋势页 → “活动报告”：昨日对比、近 7 日周报、近 30 日月报。服务器暂无接口时明确提示，并保留三项位置；不虚构数据、不将缺失记录当作零活动。

主动呼救可请求主板声光报警。页面区分记录保存、命令已提交、执行成功、失败与结果未知，不将提交成功当作板端执行成功。

## 后端交接

附带后端 API 1.8.2 源码包，不含 .env、数据库或密钥。服务器尚未部署此包；检查时公网报告接口返回 404。更新后端后，App 才能取得报告。

在原部署目录更新代码、安装 requirements.txt，保留原 .env 和数据库。沿用已有启动服务及 AMQP 消费者，不要额外启动第二个消费者。

验收：/healthz 返回 api_version=1.8.2；登录后报告接口 /api/v1/devices/{主设备ID}/reports 应返回报告结构。没有足够历史数据时应如实显示暂无对比。

远程呼救还需要在主设备产品 HomeSafety 服务添加无参数命令 sos。可先运行 tools_sos_model.py 查看缺项，再运行 tools_sos_model.py --apply 添加（需服务器现有云权限）。脚本会备份原物模型；也可在控制台手动添加。

App 的 POST /api/v1/devices/{ID}/sos 使用 activate_device=true 请求板端联动；旧客户端不传该字段时保留仅创建呼救记录的行为。重复请求以 client_request_id 去重。
