# 部署说明：App 1.16.1 / 后端 1.13.0 + 提醒接口 / ESP32-CAM v0.3.2

面向队友的落地步骤。本轮**只改代码，不改服务器状态**：仓库里的 `main` 已经是可部署状态，但线上后端、在跑的摄像头固件、手机上的 App 都还是旧版本，需要按下面的顺序各自更新一次。

| 组件 | 仓库版本 | 线上/设备现状 | 是否必须更新 |
|---|---|---|---|
| App | 1.16.1（versionCode 1016001） | 1.16.0 | 必须，本轮界面改动都在这里 |
| 后端 | 1.13.0 + `POST /alarms/{key}/remind` | 1.13.0（无提醒接口） | 必须，否则「提醒家人查看处理」返回 404 |
| ESP32-CAM | camera-v0.3.2 | v0.3.1 | 建议，修「流畅模式」永久 503 |

---

## 一、本轮改了什么

### App 1.16.1（`app/`）

1. **房门、活动记录由三级页压平为二级页**（本次主要改动）
   - 房门：点进去直接是「当前状态 + 房间读数（光照/烟雾/人体/磁簧）+ 出入记录」，不再需要再点一次「查看房间节点」。
   - 活动记录：点进去直接是「活动/报警/记录天数 + 每日活动分布 + 周报月报」，不再需要再点一次「查看活动趋势与报告」。
   - 详情页的返回按钮改为**固定在顶部**，页面下滑后仍然可见（原来会跟着内容滚出屏幕）。
   - 日期切换改为**倒序**（最近一天在最左），默认选中项不用横向滚动就能看到。
2. 首页两条入口的右侧摘要改为实时值（房门「已打开/已关闭/数据待更新」，活动记录「距上次 N 秒 / 今日 N 次」）。
3. 摄像头页：连续视频连续失败 2 次后**自动降级到省流取图**，并记住选择。
4. 后端连接超时 8 秒 → 20 秒（`/household` 在公网上常需 20 秒以上，旧超时必然失败）。
5. 只读成员可在报警详情里「提醒家人查看处理」，**可以自己勾选提醒谁**（只列出有处理权限的成员，默认全选）。
6. **报警提醒不再被历史记录刷屏**：只有 30 分钟内发生、且仍未解决的事件才会弹窗；旧记录只是留在列表里，不再每次启动都弹。
7. 弹窗底部提供「稍后查看」和「忽略全部 N 条」，一次就能清掉整队提醒（只关闭提醒，不改变报警状态）。
8. 报警列表每组默认只显示 3 条；超出部分**分批展开**——按钮显示「再看 10 条 · 还剩 N 条」，剩不到 10 条时显示「展开剩余 N 条」，全部展开后变「收起」。报警页对未标记的旧记录提供「一键标记已处理」。
9. 报警状态标签区分处置情况：设备侧已结束但已记录处理的显示「已结束 · 已处理」，一键标记后能直接看出处理过。
10. **演示模式新增「只读成员体验」开关**（我的 → 显示与提醒，仅演示模式可见）：打开后按只读成员权限展示，可在报警详情里演示「提醒家人查看处理」的选人流程；只读视角下确认/消音置灰，处理备注区不再显示可点的处置按钮。
11. **首页移除「需要帮助？/主动呼救」入口**：首页只做状态查看与日常入口，避免误触；主动呼救仍保留在报警页「更多操作」里（带二次确认）。
12. **「我的 → 家庭成员」不再有「查看家庭设备」按钮**（原来点它会把用户甩到设备标签，像"点成员进了设备页"）。现在：
    - 已登录：页面底部改为「进入家庭与账号」，成员开通与邀请统一走那一页；本页只做成员查看与账号切换。
    - 未登录 / 演示模式：明确提示"演示模式不读取真实成员"，只给「登录家庭账号」入口，不再跳到设备页。
13. **报警页顶部新增「批量处理」入口**：红条「N 条异常需要核实」右侧直接给按钮，点开选范围（当前加载的待处理记录 / 仅已结束的旧报警）→ 二次确认 → 批量写入「已处理」。原来只有滚到底部「更多操作 → 一键处理全部」才有，报警多的时候根本找不到。有处置权限（`alarms.handle`）的账号才显示。
14. **语音识别改成「模糊也能懂」**（`services/VoiceCommand.ets`）：
    - 同音字归一：识别把「颐」写成依/怡/宜、「灯」写成登/等、「度」写成渡、「报」写成抱，仍能命中同一条指令；
    - 语序不问：只要提到「灯」+「关/开」，说「把灯给我关了」「灯打开一下」都能执行；
    - 口语扩充：新增「我摔倒了 / 起不来 / 晕倒 / 求救我 / 药吃过了」等老人常用说法；
    - 没听懂时给候选：「你是不是想说『小颐开灯』」，而不是只回一句「不熟」；
    - 日常闲聊不误触发：「我要吃饭」「我有点累」「今天几号」都只回提示。

### 后端 1.13.0（`backend/`）

- 新增 `POST /api/v1/devices/{device}/alarms/{event_key}/remind`：只需要 `alarms.read` 权限，每人对同一事件 **60 秒限流**，只广播一条 `alarm_remind` 事件，**不改变报警状态、不写处理记录**。
- 请求体可带提醒对象：`{"targets":["daughter","son"]}`。服务端只接受**有 `alarms.handle` 权限**的成员，混入无权限账号直接 400；不传或为空则默认提醒全部有处理权限的成员。
- WebSocket 过滤白名单放行 `alarm_remind`，并按 `targets` 只推给被选中的成员；没有 `view` 权限的成员也能收到。

### ESP32-CAM v0.3.2（`device/esp32cam/HomeSafetyCamera/`）

- 流任务栈 8192 → 4096，并在 12KB 上传任务创建**之前**分配，避免堆碎片导致分配失败。
- `/stream-ticket` 改为按需 `ensureStreamTask()`，失败可重试，不再一次失败就永久 503（这正是「省流能看、流畅看不了」的根因）。

## 三、后端部署

生产配置：`uvicorn` 单 worker，`run.py --host 127.0.0.1 --port 8000`，nginx 在 8443 转发并保留 WS 升级头。

```bash
# 1) 备份（务必先做）
cd /path/to/backend
cp -a data/app.db data/app.db.bak-$(date +%Y%m%d)
cp -a .env .env.bak-$(date +%Y%m%d)

# 2) 只替换一个文件
#    用仓库里的 backend/backend/app.py 覆盖服务器上的同名文件
#    本轮后端没有新增依赖，无需 pip install

# 3) 重启
sudo systemctl restart yihongan-backend   # 或你们自己的进程管理方式
sudo systemctl status yihongan-backend --no-pager
```

验证：

```bash
# 健康检查
curl -sk https://127.0.0.1:8443/healthz

# 新接口存在性：未登录应返回 401（不是 404）
curl -sk -o /dev/null -w '%{http_code}\n' -X POST \
  https://127.0.0.1:8443/api/v1/devices/6acdec5b18855b39c5552ec3_TXSMART001/alarms/test/remind
```

`401` = 接口已上线；`404` = 文件没换成功或没重启。

> 兼容性：这是**新增**路由 + 一处白名单放行，旧版本 App 不受影响。回滚只需还原 `app.py` 再重启，无需动数据库。

## 四、ESP32-CAM 固件烧录

```bash
cd device/esp32cam/HomeSafetyCamera

# 编译（Arduino ESP32 core 2.0.17）
arduino-cli compile --fqbn esp32:esp32:esp32cam --output-dir build .

# 烧录（串口号按实际改，CH340 常见 COM5 / /dev/ttyUSB0）
arduino-cli upload -p COM5 --fqbn esp32:esp32:esp32cam .
```

烧录后开 115200 串口看日志，应出现：

```
[boot] YiHongAn Camera v0.3.2
[boot] cloud_enabled=1 free_heap=283464 psram=4194252
[camera] stream task ready (4096 bytes)
```

看到 `stream task allocation failed` 说明本条板子堆太碎，重启一次即可（`/stream-ticket` 会再次尝试创建）。

**两个坑（都踩过）：**

1. **不要把工程放在中文路径下编译**，xtensa-gcc 会卡死（表现为几分钟只有 0.2 秒 CPU）。复制到 `F:\hg_cam` 这类纯英文路径再编。
2. 国内拉 core 包只有 8 KB/s。需要镜像索引时，`tools[].systems[].url` 和 `platforms[].url` **两个字段都要改**，并清掉 `%LOCALAPPDATA%\Arduino15\package_index.json` 缓存。

## 五、App 构建与安装

仓库里的 `app/` 目录**不含签名配置**（`build-profile.json5` 里没有 signingConfigs）。两种做法：

**A. 用已有签名工程（推荐，队友本地已有就直接用）**

```powershell
# 在带签名配置的构建目录里
.\build-windows.ps1
# 产物：entry/build/default/outputs/default/entry-default-signed.hap
```

**B. 用 DevEco Studio 打开 `app/`**，在 Project Structure → Signing Configs 里勾自动签名后再 Build HAP。

安装到手机/模拟器：

```bash
hdc list targets
hdc install -r entry-default-signed.hap
hdc shell aa force-stop com.zhian.eldercare
hdc shell aa start -a EntryAbility -b com.zhian.eldercare
```

> 装完是「演示模式」属于正常现象，登录后才走真实数据。

## 八、已知问题（不是本轮引入的）

1. **写这份说明时线上服务器不可达**：`curl https://47.116.171.114:8443/healthz` 25 秒超时，App 登录报 `Operation timeout`。部署前先确认服务器和网络，否则会误判成 App 的 bug。
2. `remind` 的 60 秒限流是**进程内内存字典**，uvicorn 单 worker 没问题；将来扩多 worker 需要换 Redis 或落库。
3. 首页「读数同步失败…Operation timeout」是因为网关设备自 11/7 起就没再上报，`/shadow` 请求超时（8 秒固定超时），与本次界面改动无关。
4. 活动日期标签直接用了后端返回的 `day.date`，格式是 `2026-11-06`，与「每日活动分布」右侧 subtitle 一致，未做本地化。
