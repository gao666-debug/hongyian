## 三、赛题四需求拆解

**背景**：独居老人突发意外（跌倒、突发疾病、燃气泄漏）无法及时求助。

**必做功能**
1. **南向数据采集与控制**
   - 红外人体传感器：监测活动轨迹，判断是否长时间无移动
   - 门窗磁传感器：监测门窗开关，判断外出/异常出入
   - 温湿度传感器：监测室内环境舒适度
   - 老人随身无线紧急求助按钮
   - 开发板通过 GPIO/I2C 实时采集，用基础阈值算法识别异常
2. **本地声光预警与自助求助**
   - 异常时（长时间无人体活动疑似跌倒/昏迷；温湿度异常疑似空调/暖气故障）自动触发本地声光报警，提醒邻居/物业
   - 老人主动按求助按钮 → 触发本地声光报警 + 语音模块播放预设语音（如"我需要帮助"）
3. **北向数据展示（子女/监护人手机 App）**
   - 实时查看各传感器状态（人体活动最后触发时间、门窗开关记录、当前温湿度等）
   - 展示设备在线状态与电量
   - 按日期查看老人活动规律报告（如"今日活动频次较昨日下降 20%"）
   - 历史预警记录查询与详情
4. **事件闭环管理**
   - 监护人确认预警、填写处置结果（如"已联系社区网格员上门""老人一切正常，误报"）
   - 形成居家安全日志，便于长期跟踪
5. **数据统计分析**
   - 统计老人日常活动时段分布、每日活动频次趋势
   - 生成周/月报告，帮助发现生活规律变化（活动量持续下降可能预示健康问题）

**创新加分项（非强制）**
1. 多维监测：新增烟雾传感器、燃气传感器
2. 星闪自组网：多传感器与开发板低功耗自组网，解决 Wi-Fi 覆盖不全
3. 远程告警推送：4G 模组上传云端，推送到子女手机
4. 多终端协同：预警同步推送至子女、社区网格员、物业值班人员

## 五、选定技术方案（方案 A：分阶段落地 + 数据源可插拔）

**核心思想**：先用模拟数据把北向 App 做完整（保底），再逐步接南向真机（亮点），最后接通信层。

**三层架构**

```
北向应用层（鸿蒙 App，ArkTS / DevEco Studio，API 12+）
  ├─ 实时监控页
  ├─ 事件闭环页
  ├─ 统计报告页
  └─ 设备/设置页
     数据层：本地数据库 + 数据源（模拟数据源 ←→ 真机数据源，可切换）
        │
        │  HTTP/JSON（轮询）或 MQTT
        ▼
通信层（板子内置 Wi-Fi 2.4G + 支持 MQTT）
  ├─ 局域网：板子开 HTTP 服务，App 轮询
  └─ 云平台（升级项）：板子 MQTT → 云 → App 远程
        │
        │  GPIO / I2C / ADC / UART
        ▼
南向设备层（RK2206 通晓板，OpenHarmony LiteOS，C）
  采集：人体 · 温湿度 · 燃气 · 光照 · 加速度(MPU6050) · NFC
  逻辑：采集 → 阈值判断 → 触发本地声光报警 + SU-03T 语音
```

**三个设计原则**
1. **数据源可插拔**：App 里把"取数据"抽成接口，前期模拟数据源，后期换真机数据源，页面代码几乎不改。
2. **南向独立可演示**：板子"采集 + 本地报警"不依赖 App，单独可演示，风险隔离。
3. **必做优先、创新后置**：先做齐 5 个必做功能，燃气/NFC/语音/跌倒检测等加分项最后加。

**技术栈**
- 北向：DevEco Studio + ArkTS/ArkUI + 关系型数据库(RDB)/Preferences + `@ohos.net.http`（或 MQTT）
- 南向：RK2206 OpenHarmony 南向开发（C，HDF 驱动 + GPIO/I2C/ADC/UART）
- 通信：板子端轻量 HTTP Server 或 MQTT client

## 六、南向开发环境搭建（来自官方实验手册）

**环境架构**：Windows 工作台 + WSL2(Ubuntu 20.04) + Docker 编译容器

**步骤**
1. 启用 Windows 功能：`适用于 Linux 的 Windows 子系统` + `虚拟机平台`
   - 命令：`dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart`
   - `dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart`
2. 安装 WSL2 Linux 内核更新包；`wsl --set-default-version 2`
3. Microsoft Store 安装 **Ubuntu 20.04 LTS**，创建 `openharmony` 用户
4. 安装 **Docker Desktop**（Windows）
5. 拉取编译镜像：
   `docker pull swr.cn-south-1.myhuaweicloud.com/openharmony-docker/openharmony-docker:1.0.0`
   重命名：`docker image tag ... openharmony-docker:1.0.0`
   运行：`docker run -it openharmony-docker:1.0.0`
6. 获取源码（容器内）：
   `git clone https://gitee.com/isoh_edu/txsmartropenharmony.git`
   （小凌派 RK2206 / OpenHarmony 3.0 LTS）
7. 用 VS Code + Dev Containers 扩展 attach 进容器，打开 `/home/openharmony/`
8. 编译：
   - 首次：`pip install build/lite`（hb 工具降级为 0.4.3）
   - `hb set`（选产品，root path 输入 `.`）
   - `hb build -f`
   - 固件在 `out/.../images` 下
9. 烧录：
   - 安装 `device/.../tools/windows/DriverAssitant/DriverInstall.exe`
   - USB 连接开发板烧写口，打开 `RKDevTool.exe`，导入 bootloader + firmware
   - **按住 mask 键 → 再按 reset 键** 进入 MASKROM 模式
10. 看日志：装 CH340 驱动，MobaXterm → Serial，波特率 115200

**代码编写示例路径**（来自使用手册）
- 新建模块：`/vendor/isoftstone/rk2206/samples/hello/`
- 示例 hello.c：
  ```c
  #include "ohos_init.h"
  int hello_example() { printf("Hello World!\n"); return 0; }
  APP_FEATURE_INIT(hello_example);
  ```
- BUILD.gn：
  ```gn
  static_library("hello") {
    sources = [ "hello.c" ]
    include_dirs = [ "." ]
  }
  ```
- 并在 `vendor/isoftstone/rk2206/samples/BUILD.gn` 与 `device/rockchip/rk2206/sdk_liteos/Makefile` 中登记模块
