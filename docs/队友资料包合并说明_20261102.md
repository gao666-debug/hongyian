## 配置与发布边界

1. 不覆盖 `.env`、数据库、证书、私钥及 App 私有配置；不自动启动消费者，避免与线上消费者争抢消息。
2. 后端源码已整合，但未部署服务器。部署前备份数据库、抓拍目录及源码，填写实际配置后运行测试，再切换服务。
3. `DEVICE_ID` 第一台为主设备，不要填成环境节点；手表填 `WATCH_DEVICE_ID`。家庭接口登录响应会按账号返回授权设备，可能包含手表，与原线上只返回两台设备的行为不同。
4. 环境节点若仅列在逗号白名单中，沿用队友行为：属性通知忽略，`device_health` 入库；显式设置 `NEARLINK_A_DEVICE_ID` 后额外支持环境属性快照，绝不会送入手表归一化。
5. 环境节点配置先从 `src/cfg.example.h` 复制为本机 `src/cfg.h`。其 MQTT password 是签名结果，不是原始设备密钥。
6. 规则必须启用并将需要的消息/属性通知送往后端实际使用的 AMQP 队列。同名 MQTT Topic 不等于 AMQP 队列。
7. 原包中的主板只有烧录产物，没有业务源码；此次保留本机主板源码，不用来源不明的固件替换。编译镜像不进入源码仓库。
8. 本次不修改 App 页面；原有湖蓝主题与摄像头功能仍在 App 工程及 PR #3 中。
