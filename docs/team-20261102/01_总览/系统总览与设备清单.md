## 三、真实上报 JSON（含单位与频率）

### 3.1 环境节点 · 属性上报

**Topic**：`$oc/devices/demo-environment/sys/properties/report`
**频率**：10 秒一次；门磁/人体变化时立即补发（最小间隔 1 秒）
**报文**（格式来自 `src/iotda.c:161-167`，字段值取自真机影子）

```json
{
  "services": [
    {
      "service_id": "11",
      "properties": {
        "light": 507,
        "smoke": 159,
        "body": 1,
        "door": "OPEN"
      }
    }
  ]
}
```

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `light` | uint | **ADC 电压 mV（0~3300）** | 光敏电阻分压，**不是 lux、也不是百分比** |
| `smoke` | uint | **ADC 电压 mV（0~3300）** | 烟雾传感器模拟输出 |
| `body` | uint | 0/1 | 人体感应：1=有人 |
| `door` | string | — | `OPEN` / `CLOSED`（磁铁靠近=高电平=CLOSED） |

### 3.2 环境节点 · 自定义消息上报

**Topic**：`$oc/devices/demo-environment/sys/messages/up`
**频率**：与属性上报同一次触发，两条一起发
**报文**（格式来自 `src/iotda.c:173-183`）

```json
{
  "name": "device_health",
  "id": "ws63-1793530204-42",
  "content": {
    "fw": "ws63-home-1.0",
    "boot_id": 1793528072,
    "epoch": 1793530204,
    "up": 2136,
    "env_valid": 1,
    "imu_valid": 0,
    "door_enabled": 1,
    "wireless_btn_enabled": 0,
    "mute": 0,
    "tls": false,
    "light": 507,
    "smoke": 159,
    "body": 1,
    "door": "OPEN"
  }
}
```

| 字段 | 单位/取值 | 说明 |
|---|---|---|
| `id` | 字符串 | **每条必须唯一**，后端用 `INSERT OR IGNORE` 去重，重复会被丢掉 |
| `boot_id` | Unix 秒 | 本次开机时刻，用于判新旧（`(boot_id, up)` 回退的消息会被拒） |
| `epoch` | Unix 秒 | 设备当前时间（SNTP 校时后） |
| `up` | 秒 | 本次开机时长 |
| `tls` | bool | 是否走 MQTTS |
| `light` / `smoke` / `body` / `door` | 同 3.1 | 同一份快照 |

### 3.3 手表 · 属性上报

**Topic**：`$oc/devices/demo-watch/sys/properties/report`
**频率**：10 秒一次
**报文**（格式来自 `src/hy_cloud.c:133-139`，字段值取自真机影子 11-01 11:44）

```json
{
  "services": [
    {
      "service_id": "11",
      "properties": {
        "heart_rate": 100,
        "spo2": 99,
        "accel_x": -61,
        "accel_y": -330,
        "accel_z": 920,
        "steps": 11,
        "fall_state": 0,
        "fall_count": 0
      }
    }
  ]
}
```

| 字段 | 单位 | 说明 |
|---|---|---|
| `heart_rate` | bpm | **0 表示这次没测到**（手指没贴），不是"心率 0" |
| `spo2` | % | 0 同上 |
| `accel_x/y/z` | **mg（毫 g）** | ±8g 量程。静止时模长约 1000 |
| `steps` | 步 | 上电以来累计，**重启归零** |
| `fall_state` | 0/1/2 | 此刻状态：0 正常 / 1 冲击后观察中 / 2 疑似摔倒 |
| `fall_count` | 次 | 上电以来累计摔倒次数，**重启归零**（不能做历史统计） |

### 3.4 主监护板 · 健康上报

**通路**：MQTT 消息 → `device.message`（后端 `Health` 模型解析）
**频率**：约 60 秒一次

> ⚠️ 主板的**原始报文格式没有从源码确认**（主板源码不在本机，见 `02_主板_RK2206/主板说明.md`）。
> 下面给的是**真机上报、经后端解析后**的结构（`GET /devices/{id}/health` 的真实返回），
> 字段名与语义可信，但原始 JSON 的字段顺序/可选字段以主板固件为准。

```json
{
  "schema": 1,
  "fw": "v3.5.42",
  "boot_id": 556,
  "epoch": 1793551913,
  "up": 1234,
  "env_valid": 1,
  "imu_valid": 1,
  "door_enabled": 0,
  "wireless_btn_enabled": 0,
  "mute": 0,
  "tls": false,
  "living": {
    "schema": 2,
    "config_revision": 22,
    "night_auto": true,
    "night_on": true,
    "light_valid": true,
    "light_owner": "night",
    "medicine_enabled": true,
    "medicine_minute": 480,
    "medicine_state": 2,
    "dose_day": 20759,
    "confirmed_epoch": 0,
    "time_synced": true,
    "medicine_revision": 40,
    "slots": [
      { "slot": 0, "enabled": true,  "minute": 480,  "state": 2, "confirmed_epoch": 0 },
      { "slot": 1, "enabled": true,  "minute": 720,  "state": 2, "confirmed_epoch": 0 },
      { "slot": 2, "enabled": false, "minute": 1200, "state": 0, "confirmed_epoch": 0 }
    ]
  },
  "door_valid": 0,
  "sample_up": 1234,
  "sample_age_s": 0,
  "data_state": "ready",
  "data_stale": false,
  "env_available": true,
  "fall_detection_available": false,
  "time_synced": true
}
```

| 字段 | 单位/取值 | 说明 |
|---|---|---|
| `schema` | 1 | 报文结构版本 |
| `living.slots[].minute` | **当天第几分钟** | 480 = 08:00，720 = 12:00，1200 = 20:00 |
| `living.slots[].state` | 0/1/2 | 2 = 待确认（到了服药时间还没确认） |
| `living.medicine_revision` / `config_revision` | 整数 | 乐观锁版本号，下发命令必须带 `expected_revision` |
| `data_stale` | bool | true 表示数据过期，界面应置灰 |
| `sample_age_s` | 秒 | 上次采样距今多久 |

## 四、是否支持命令下发

| 设备 | 支持 | 可用命令 | 说明 |
|---|---|---|---|
| **主监护板** | ✅ **支持** | `ack`（消警）<br>`mute`（静音）<br>`set_living`（夜间灯等）<br>`confirm_medicine`（确认服药）<br>`set_medicine_plan`（设三次服药时间）<br>`set_medicine_state`（单次确认/撤销） | 走 `POST /api/v1/commands`，后端转成 IoTDA 同步命令 |
| **环境节点** | ❌ **不支持** | — | 固件只上报，没订阅命令 Topic。后端若强发会等 15 秒超时返回 `state=unknown` |
| **手表** | ❌ **不支持** | — | 同环境节点；App 不要给它渲染任何操作按钮 |

**主板的命令下发细节**：

```json
POST /api/v1/commands
{
  "device_id": "demo-device",
  "service_id": "HomeSafety",
  "command_name": "confirm_medicine",
  "paras": { "slot": 0, "taken": true, "expected_medicine_revision": 40 },
  "client_request_id": "living-1793551913000-12345"
}
```

- 返回 **202** + `command_id`，需要轮询 `GET /api/v1/commands/{command_id}` 拿结果
- `state` 取值：`pending` / `executed` / `failed` / **`unknown`**
- `unknown` = 网络超时，**无法确定设备是否执行**，UI 应提示"状态未知"而非"失败"
- 带 `revision` 的命令（服药相关）如果不带或带错版本号，会被设备拒绝

## 五、一块补充：手表为什么不在设备列表里

系统有 **3 块硬件**，但 App 只看到 **2 台设备**。

原因：手表是「人」身上的穿戴设备，它的数据**挂载在主监护板名下**
（数据库 `device` 字段写的是主板的 device_id），App 通过
`GET /api/v1/devices/{主监护板的ID}/watch` 读取。

这样 App 不用维护"这台是主板还是手表"的分支，「主板 + 手表 = 一个被监护的人」。
