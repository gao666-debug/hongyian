## 三、环境配置步骤

- [ ] 建立独立工程目录，例如 `~/nearlink/ws63_ohos`，与现有 RK2206 工程分开。
- [ ] 如使用 Docker Desktop，启用对应 WSL 发行版的集成，验证容器可访问工程目录。
- [ ] 按官方或套件匹配版本下载源码、预编译依赖和 RISC-V 交叉编译器。
- [ ] 确认编译器能运行、依赖齐全、源码不是 Git LFS 占位文件。
- [ ] 按套件原理图核对板级配置，不直接使用其他厂家参考板的引脚和固件。
- [ ] 按套件教程接入 demo 的 Kconfig/CMake 配置；只启用一个基础实验，避免示例争用引脚。

套件教程使用的 SDK 目录及构建入口如下，须先确认所取得的 SDK 支持：

```text
device/soc/hisilicon/ws63v100/sdk
```

```bash
# 在上述 SDK 根目录执行
./build.py menuconfig ws63-liteos-app
./build.py -c ws63-liteos-app
```

教程给出的固件位置：

```text
output/ws63/fwpkg/ws63-liteos-app/ws63-liteos-app_all.fwpkg
```

官方外层 OpenHarmony 工程另有 `hb set` / `hb build` 路线；应按所选 SDK 配套说明执行，不能混用入口。官方指南中的参考板目标不等于本套件已适配目标。

## 四、基础验收顺序

- [ ] 两块板先分别 USB 供电，不接新增门磁、433MHz 接收模块。
- [ ] Windows 能识别 COM 口，串口工具能正常打开。
- [ ] 基础线程或 LED 示例可编译，保存完整成功日志。
- [ ] 使用 BurnTool、正确的 WS63 目标和 `.fwpkg` 烧录，串口输出与实验预期一致。
- [ ] 分别验证按键、OLED、温湿度；记录实际串口参数。
- [ ] 两块板均无异常重启、卡死，再进行 SLE 收发测试。
- [ ] 验证星闪断开后可重连，重复消息不会重复执行业务。
- [ ] 若承担网关职责，实测 Wi-Fi 与 SLE 同时运行。

**完成标准：另一台电脑能按记录复现“编译 → 烧录 → 串口运行”，才算环境交付完成。**

## 五、后续开发分工建议（待实现）

| 设备 | 建议职责 |
| --- | --- |
| 原 TX-SMART-R / RK2206 | 保留现有环境监测、屏幕、语音、夜灯、服药提醒和云端链路 |
| 星闪板 A + 家居扩展板 | 房间节点，后续接入门磁、433MHz 接收模块 |
| 星闪板 B + 手表扩展板 | 求助、服药确认、心率血氧点测和运动信息 |

- [ ] 先跑通两板 SLE 通信，再决定哪块作为中心/网关。
- [ ] 新增外设根据星闪板原理图重新分配 GPIO，不能沿用 RK2206 的 B6/B7 等接线。
- [ ] 核实扩展口供电余量和信号电平后再接模块，目前不能承诺无需额外电源。
- [ ] 433MHz 遥控器仍需原接收模块解码，再由星闪板处理事件。
- [ ] 不假设 RK2206 原生支持星闪；与原系统的协同方式另行确定。
- [ ] 若新节点独立上云，使用独立设备身份；若网关汇总，消息须区分节点来源。
- [ ] 不把固定桌面板子的加速度数据直接当作老人跌倒；健康数据先判断有效性。
