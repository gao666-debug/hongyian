# 鸿颐安架构与协作规划

## 当前与后续边界

现有后端与 App 源码以 TX-SMART-R 主板为基础。ESP32-CAM 已独立验证本地浏览器实时观看；摄像头 App 集成、多设备后端、跨板联动尚未完成。

## 设备分工

| 设备 | 职责 |
| --- | --- |
| TX-SMART-R | 固定居家终端：环境、活动、语音、夜灯、服药、显示和本地警报 |
| 星闪 A | 房间节点／网关：房门、无线按钮，转发穿戴节点 |
| 星闪 B | 穿戴节点：求助、确认，**已实现手腕端健康采集与摔倒检测并直连 IoTDA** |
| ESP32-CAM | 本地实时画面、截图，后续接入报警抓拍 |

固定主板加速度计不能直接作为老人跌倒检测依据。SLE 与 Wi-Fi 同时运行须由星闪固件实测确认。

### 穿戴节点当前实现（2026-11-01）

WS63 手表是一台**独立直连 IoTDA 的设备**（独立设备 ID 与密钥），不经网关转发：

- 采集：MPU6050（±8 g / 100 Hz）+ MAX3010x（200 Hz），心率自相关算法、计步、摔倒状态机；
- 上报：每 10 s 一条属性（心率、血氧、三轴 mg、步数、跌倒状态与累计次数），摔倒判定当次立刻补报；
- 后端：`device.property/report` 走 AMQP 进后端，归一化后落 `watch` / `watch_hour` / `watch_fall`，
  WebSocket 推送 `watch`、`watch_fall`，App 用 `/watch` 三个接口读。

后续若要改成"经网关转发"，设备身份可保留为云端子设备；当前先按直连验证，避免网关方案未定就耦合进来。

## 云与后端

共用一个 IoTDA 实例；每个独立直连设备使用独立身份。穿戴节点经网关转发仍保留来源标识；是否使用云端子设备待网关方案验证。App 通过后端鉴权，不使用硬件 MQTT 身份或云账号密钥。

后端逐步增加家庭设备绑定、设备状态与更新时间、事件来源、命令回执与幂等、联动规则。处理记录与设备确认分开；环境危险持续时，确认操作不清除传感器异常。

摄像头外网观看需要主动出站连接或转发机制，服务器不能直接访问家庭私网 IP。优先图片上传和局域网观看，再考虑外网视频。

## 实施顺序

1. 整理接口，保持现有单设备兼容。
2. 后端多设备模型与 App 页面。
3. 星闪 A/B 接入及无线求助闭环。
4. 摄像头报警抓拍与 App 本地观看。
5. 实测断线恢复、权限及重复命令，再扩展外网视频与跌倒检测。

## 协作

分支开发后提交 Pull Request。环境配置各自在本地保存；只提交 `.env.example`。代码发布、后端部署、App 分发和固件更新是独立步骤。
