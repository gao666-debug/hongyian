# 颐鸿安 · 参数速查（"这个值在哪改"）

> 格式：**值 → 文件:行 → 现值 → 改完怎么生效**
> 路径可整段复制。**阈值类多数是运行期配置，现场下发即生效**；只有真编进固件的常量才需要重烧（见第六节）。App 改完要重构建 + 安装；后端改完要部署 + 重启。

## 一、主板 RK2206（居家守护主机）

**目录：`F:/鸿蒙比赛/提交_20261106/repo/device/rk2206_home_safety`**

### ⚠️ 先看这条：`home_safety.h` 里的阈值宏改了不生效

已逐个 grep 核实：`TEMP_HIGH_LIMIT`、`TEMP_LOW_LIMIT`、`HUMI_HIGH_LIMIT`、`HUMI_LOW_LIMIT`、`GAS_PPM_LIMIT`、`NO_ACTIVITY_TIMEOUT_MS`、`ALARM_MUTE_MS` 在**任何 `.c` 里都没有被引用**（只剩头文件里的定义和注释）。真正生效的值分三层：

| 层级 | 位置 | 说明 |
| --- | --- | --- |
| ① 实际运行值 | KV 存储 `cfg_num<槽位>`，掉电保持 | 判定时读 `cfg.temp_high` 等，不是读宏 |
| ② 出厂默认值 | `src/safety_runtime.c:98-111`（首次开机）与 `:175-187`（KV 校验失败兜底） | **改这里的字面量才影响"新板子"** |
| ③ 无效宏 | `include/home_safety.h:25-49` | 历史遗留，仅供阅读，无代码引用 |

② 里这 12 个值的顺序是固定的：
`port, report_ms, noact_ms, mute_ms, temp_low, temp_high, humi_low, humi_high, gas_limit, demo`
现值 = `1883, 15000, 60000, 30000, 10, 35, 20, 80, 800, true`
即：上报 15 秒、无活动 60 秒、静音 30 秒、温度 10～35℃、湿度 20～80%、燃气 800 ppm。

**还有一个坑**：老板子 KV 里已经有旧配置时，就算你改了默认值重新烧录，启动仍优先读 KV → 新默认值不生效。要么用 `/config` 覆盖一次，要么清 KV。

### 环境报警阈值（温度/湿度/燃气）—— 可现场改，不用重烧

`/config` 接口本身支持这几个字段（`src/safety_runtime.c:345-349`），只是**本地网页没做输入框**。配对后在网页控制台执行一行即可，立即生效并掉电保存：

```js
// 在本地网页（http://板子IP:8080）的控制台执行，需先按 K5/K6 完成配对
await api('/config',{method:'POST',
  headers:{'Content-Type':'application/json','X-Care-Local':'1'},
  body:JSON.stringify({temp_high:32})})
```

支持字段与合法区间（`src/safety_runtime.c:85-94` 整包校验，任一项不合规整体拒绝、不会写半套）：

| 字段 | 区间 | 现值 |
| --- | --- | --- |
| `temp_low` / `temp_high` | -40～125℃，且 low < high | 10 / 35 |
| `humi_low` / `humi_high` | 0～100%，且 low < high | 20 / 80 |
| `gas_limit` | 1～100000 ppm | 800 |
| `mute_ms` | 1000～600000 ms | 30000 |
| `noact_ms` | 10000～86400000 ms | 60000 |
| `report_ms` | 1000～3600000 ms | 15000 |

判定处：`home_safety_example.c:507-510`（`cfg.temp_high`、`cfg.gas_limit`）。

> 烟雾阈值 `SMOKE_PPM_LIMIT 2000`（`home_safety.h:37`）是**唯一真在用的宏**（`home_safety_example.c:510`），改它必须重烧。

### 跌倒检测：主板不参与判定

`home_safety.h:42-45` 那四个 `FALL_*` 宏确实被 `src/safety_logic.c:20-53` 引用，但**主流程从未调用 `safety_fall_sample()`**（全仓 grep 无调用点），MPU6050 只被初始化、读到数据也不送进判定。头文件原注释即写明："The fixed gateway does not use board motion to detect human falls. **Do not drop or throw the development board to demonstrate this feature.**"

所以现场讲跌倒，讲手表的参数（见第三节），不要讲主板这组。

## 六、⚠️ 改完怎么生效（被追问时的标准回答）

| 改的是 | 生效方式 |
| --- | --- |
| 主板**出厂默认值** `src/safety_runtime.c:98-111` | 重新编译固件 → RKDevTool 烧 `Firmware.img` → 断电重启（老板子还需清 KV 或用 `/config` 覆盖） |
| 主板**真在用的宏** `SMOKE_PPM_LIMIT`、`FALL_*`（后者未接线） | 同上，必须重烧 |
| 摄像头 `.ino` | Arduino IDE 编译 → OTA 或串口烧录 |
| 手表 | WS63 SDK 重编 → 烧录 |
| App | `F:\hongyian-app-build\build-windows.ps1` 构建 → `hdc install -r` 覆盖安装 |
| 后端 | 传到 `/home/deploy/app` → `systemctl --user restart eldercare-api` |
| **不用重烧的** | 温度/湿度/燃气阈值、报警静音、上报间隔、Wi-Fi 名称密码（`/config`）；无活动阈值、睡眠时段、暂停（`/care-policy`）；服药时间、夜灯模式（`/living`）—— 全都能现场下发，且掉电保存 |

> 被追问时的准确回答：**阈值不是写死的常量，是运行期配置**。温度/湿度/燃气/静音/上报间隔走 `/config`，无活动与睡眠时段走 `/care-policy`，服药与夜灯走 `/living`；这些改完立即生效并写进 KV 掉电保存，不用重新烧录。只有烟雾阈值和摄像头画质这类编进固件的值才需要重烧。
>
> 追问"那 `home_safety.h` 里那堆 `#define` 是什么"→ 如实答：那是早期版本遗留的常量，现在判定统一读 `cfg`，宏已不参与运算。
