# 鸿颐安圆屏固定引脚测试：HY-LCD-ONLY-1

## 先看这一条

这是可构建的测试源码，不是已验证亮屏的二进制。主机测试通过不等于实板已显示。
使用现有 WS63 SDK 编译，确认串口出现 `BUILD=HY-LCD-ONLY-1`；最终成功必须肉眼看到颜色变化。
后端、App、云端配置都不需要改动。

## 连接对象必须说清

- EXB：带 USB、主控和 A/B/C/D 按键的底板。
- WEAR：装有 MPU6050、MAX30100 和七针圆屏插座的黑色手表扩展板。
- 圆屏：蓝色 GC9A01 240×240 模组。
- EXB 上四针 `GND/VCC/SCL/SDA` 的 LCD1 是 I2C OLED 插座，不能直插七针 SPI 圆屏。

若“拔掉 WEAR 后仍能读到两种传感器”，请先核对实际拆下的是圆屏还是整块黑色 WEAR。
记录每组实物照片；每次断电拆装、清空串口接收区、重新上电。不能根据旧日志认定传感器位置。

## 固定接法

依据 EXB V1、WEAR V0 第 1 页，预期对接如下；插接方向仍须按实物确认。

| 圆屏 | WEAR | 底板网络 / SDK 示例引脚 |
| --- | --- | --- |
| VCC | J1-12 | 5V0（按原套件接法；不能据此推广到其他屏） |
| GND | J1-10 | GND |
| SCL/CLK | J2-8 | IO7 / 7 |
| SDA/MOSI | J1-9 | IO9 / 9 |
| DC | J1-8 | IO10 / 10 |
| CS | J1-7 | IO11 / 11 |
| RST | J1-6 | IO12 / 12 |

WEAR J2-7 是 MPU6050 ADO，J2-6 是 AUX_CL，J2-4 是 Sensor_INT。旧文档把针号读错而推导出 IO8，不能继续使用该推论。连接器名 LCD1 在两块板上指不同接口。

## 如何使用（建议使用安装脚本）

在你电脑的 hongyian 仓库根目录运行。`D:/ws/src` 是队友记录中的 SDK 根目录示例，须能找到 `build.py`。

```powershell
git pull origin main
python device/203_watch/tools/install_lcd_only.py --sdk D:/ws/src
```

脚本自动完成：

1. 备份 SDK 内旧 `203_watch`、demo CMake/Kconfig、目标配置，目录为 `SDK/hongyian-backups/<时间>/`。
2. 只复制四份最小圆屏源码，并写入只编译两个 C 文件的 CMake；即使 SDK 保留旧 `lcd_diag.c`，也不会编译它。
3. 目标配置只启用 `CONFIG_SAMPLE_SUPPORT_203_WATCH=y`，关闭其他 `CONFIG_SAMPLE_SUPPORT_*=y`，保留其他配置。
4. 备份后移除 `output/ws63/acore/ws63-liteos-app/cmake_command.txt`，使下一次构建重新配置。

若目录结构不同，显式指定：

```powershell
python device/203_watch/tools/install_lcd_only.py --sdk D:/ws/src --demo-dir D:/ws/src/application/samples/demo --config D:/ws/src/build/config/target_config/ws63/menuconfig/acore/ws63_liteos_app.config
```

文件路径不匹配会报错；不要凭空创建错误的 SDK 目录。然后在你原先可用的构建终端执行：

```bash
cd /d/ws/src
source /d/ws63/env.sh
python build.py -nhso -j8 ws63-liteos-app
```

构建输出必须含 `HY-LCD-ONLY-1`；源码列表应包含 `lcd_only_main.c`、`lcd_bringup.c`，不包含 `watch_ui.c`、`lcd_diag.c`、`board_check.c`、`watch_sensor.c`。
使用现有已验证烧录流程选择本次构建的 SDK 产物，通常是 `output/ws63/fwpkg/ws63-liteos-app/ws63-liteos-app_all.fwpkg`。
不要直接使用硬编码旧路径的自定义打包脚本，否则可能再次烧录旧版本。记录新产物时间和 SHA256：

```powershell
Get-FileHash D:/ws/src/output/ws63/fwpkg/ws63-liteos-app/ws63-liteos-app_all.fwpkg -Algorithm SHA256
```

烧录后断电再上电，串口 115200，检查以下标记。如果仍出现 `[dg]` 或 `[bc]`，不是本测试入口。

```text
[hy-lcd] BUILD=HY-LCD-ONLY-1 <build date/time>
[hy-lcd] GC9A01 240x240 CLK=7 MOSI=9 DC=10 CS=11 RST=12
[hy-lcd] I2C=OFF scans=OFF; use WEAR 7-pin LCD1, NOT EXB 4-pin OLED
[hy-lcd] init bytes sent; this does NOT confirm visible display
[hy-lcd] frame=0 begin=RED
[hy-lcd] frame=0 sent=RED elapsed_ms=... rc=0x00000000; VISUAL CHECK REQUIRED
```

依次循环红、绿、蓝、白、黑、六色竖条。每次完成后保持 3 秒；软件 SPI 刷新本身另需时间，不能把循环误认为固定 3 秒一帧。

## 这版实际更改

- 默认只编译圆屏测试；不运行传感器或任何引脚扫描。
- 固定 7/9/10/11/12，仅操作这五个引脚。
- 保留配套 `200_lcd_display` 的 50 条初始化命令和参数（含 RGB565 `COLMOD=0x05`）。
- 一个命令与其参数保持 CS 低；整帧 RAMWR 和像素也在同一次 CS 内。
- 时钟低电平空闲，上升沿采样，MSB 优先，每半周期显式延时 2 微秒。实际频率必须测波形，不能用帧耗时认定。
- 上电等待、硬复位及退出休眠等待；逐行喂狗，每四行让出调度。
- 地址上限 239，不写到 240；完整帧 57,600 个 RGB565 像素。
- GPIO 配置或写入失败打印完整错误并停止发送，不会反复搜索引脚。
- 原正常应用入口移除自动 `board_check_run()`；默认最小测试通过后才考虑恢复综合表盘。

## 如果仍灰屏

先回传完整启动日志和颜色循环视频，确认新程序实际运行。`rc=0` 只表示 API 调用未报错，不表示屏幕收到了数据。

接下来使用同一份固件逐项核实：

1. 断电核对实际插接、电源和地的位置，再检查圆屏插座至底板五根信号的通断。
2. 板级走线应低阻；若测量路径经过屏模组串联电阻，不能要求低于 5Ω 或必须蜂鸣。记录测量端点和实际阻值。
3. 上电测实际电压；屏模组三脚 U3 的型号和引脚需先确认，不能凭外形指定输出端。
4. 在屏端检查 RST、CLK、MOSI、DC、CS 的实际波形；主控自身 GPIO 回读不能代替这一步。
5. 换屏或整块 WEAR 时每次只改一个变量。不做带电插拔，不将七针圆屏插四针 OLED 座。

读回全 FF 不是屏坏的充分证据；总线超时也不是器件损坏的充分证据。
